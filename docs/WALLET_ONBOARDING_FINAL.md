# Wallet onboarding

Start Windows development with `cd D:\REEKLAIM` and `.\scripts\Start-ReeKlaim.ps1`. In the QoreX browser use http://127.0.0.1:5173. Keep the host and port unchanged. For a separate standalone build use `PORT=4399` and `APP_ORIGIN=http://127.0.0.1:4399` in that process. Vite preview is port 4173 and needs its own matching APP_ORIGIN.

Public header, hero and closing CTA use the same Connect Wallet controller. It opens a connection dialog on the current page. After QoreX returns the native account, the dialog switches to sign-in. An unanswered connection times out after 30 seconds. Closing the dialog stops the app waiting for the current attempt, and a late response cannot complete that attempt. Explore remains public. A first-time user reviews the Diana 1 uqor self-send and gas disclosure, consents, and separately approves in QoreX. The established server independently checks the receipt before issuing an opaque cookie. The user enters a display name and acknowledges terms in sign-in. The profile update and audit event are transactional. The dashboard opens after onboardedAt exists. Returning users with the same verified wallet and completed profile skip signup. A same-tab connection hint only attempts a passive wallet read after a valid server session returns. It stores no authorization. An expired session requires proof. Detected wallet switches or disconnects hide the previous workspace and revoke the session.

The signer retains the existing native route. The reviewed provider supports signAndBroadcast and lacks verified released SIWQ/ADR-36 support. Gas and possible key-binding costs are separate. A hash can be reconciled without re-sending. [QoreX integration](https://docs.qorechain.io/developer-tools/qorex-integrations/)
