The two refusals do not prove RPC, REST, database, cookies or wallet support caused Vincent’s original incident. The first exact error proves server-side Host rejection; the second is a disjunction, and original request headers, URL, process command and config source are absent. Both messages can arise from one Host mismatch. Compare the sanitized Network panel Host or authority, Origin, Sec-Fetch-Site, HTTP status and API path against APP_ORIGIN. Strip cookies and CSRF headers before sharing.

With the Node build configured for http://127.0.0.1:4399, a local request using localhost:4399 as Host reproduced both strings on their respective routes. At the canonical host the auth route reached query validation and the public treasury balance returned a numeric amount field. Native and EVM health passed. The exact browser prefix comes from WalletProvider.tsx:41. This isolates the reproduced refusal to origin routing before chain reads. Local config is http://127.0.0.1:5173. localhost is a different host and origin. Port 4173 preview or 4399 standalone requires an explicit APP_ORIGIN override including that port. Production requires HTTPS, no trailing slash/path, relative browser API paths, server-only URLs and independent keys. Vite registers middleware in-process for dev/preview; it does not configure an HTTP proxy to a second API server. Dist-only hosting has no API middleware. Standalone server/start.ts mounts both middleware stacks. There is no general cross-origin CORS scheme. The cookie is host-only, HttpOnly and SameSite=Lax, Secure and __Host-prefixed on HTTPS. HTTP development and HTTPS sessions are separate. Same host on another port can share a cookie, but origin-bound mutations still require the configured port.

Challenge path: /api/auth/session → guest pre-session and CSRF → /api/auth/challenge → approved native Diana 1 uqor self-send → /api/auth/verify → independent raw/REST receipt and PQ verification → atomic challenge consumption and opaque account cookie. Bootstrap can return 503 for missing configuration or failed DB readiness. Production role/TLS/forced RLS gates are in server/auth/db.ts and config.ts. WalletProvider uses the official native detector; src/wallet/adapter.ts checks Diana and optionally the exposed EVM chain. Balance uses same-origin fixed Diana reads; balance failure does not invalidate an otherwise usable wallet connection. Sign-in separately requires supported native broadcasting.

The official extension integration and installed qorex-types expose native signAndBroadcast and refuse ADR-36 signArbitrary. No signSiwq appeared on the supported extension surface reviewed. The QoreSign library publishes a SIWQ hybrid protocol. Extension support must be verified separately by wallet version and actual capability before adding that pathway. Use the existing native flow meanwhile, with explicit approval and gas disclosure.
